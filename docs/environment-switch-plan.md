# KaliMac 详细任务计划：项目环境切换与单代回退

> 状态：**计划草案，未执行**。
> 本文仅定义后续开发任务；创建本文不代表授权执行其中的命令。
> 本轮不开发、不切换分支、不运行测试、不操作容器、不提交、不推送。
> 建议后续开发分支：`codex/environment-switch`，尚未创建。

## 1. 背景与核心目标

当前已有项目初始化、工具执行、交互 shell、状态诊断、会话恢复和工具发现。
剩余核心断点是：用户发现缺失工具并自行准备新镜像后，缺少可靠的项目环境替换与回退入口。

本阶段目标：在不删除原有环境、不自动终止活跃任务的前提下，显式切换当前项目使用的镜像；
失败或中断有清晰恢复路径，新环境不合适时可以退回上一代。

完成后的用户流程：

```text
km tools 发现需求
→ 用户自行准备本地镜像
→ 预览切换影响
→ 显式切换
→ 在新环境执行工具
→ 必要时回退上一代
```

成功不是“docker run 返回 0”，而是配置、当前容器、镜像身份、会话门禁和恢复记录一致。

## 2. 范围与明确非目标

### 2.1 第一版范围

- `km env switch --image <ref>`：切换至已存在于当前本地引擎的镜像。
- `km env switch --image <ref> --dry-run`：只读预检和影响预览。
- `km env rollback`：回退最近一次成功 switch 保留的上一代。
- `km env rollback --dry-run`：只读预览回退条件与影响。
- `km env recover --dry-run` / `km env recover`：明确恢复未完成事务；此命令不表示回退正常使用中的环境。
- 状态、doctor 与帮助识别当前代、上一代和未完成事务。
- 只支持已有且身份完整的项目；切换不改变项目根、项目 ID 或平台。
- 记录所有本功能创建/保留的容器完整 ID、角色及对应事务，支持可核验的后续人工清理。

`recover` 是本功能的中断恢复组成部分，不是独立扩展方向。若合同阶段能证明已有入口可以
无歧义承担相同职责，可合并入口，但不得省略恢复能力或依赖手工修改状态文件。

### 2.2 本轮不做

- 自动拉取、自动构建镜像、自动 apt 安装、镜像发布。
- 跨架构切换、跨 Docker 引擎迁移、跨项目操作。
- 自动取消任务、强制切换、跳过身份校验。
- 自动迁移容器可写层、用户数据快照或文件级回滚。
- 任意多代回退选择、自动垃圾回收、全局容器清理。
- GUI、插件系统、全仓库重构或性能优化。
- 自动提交、推送、打 tag、升级版本号或正式发布。

## 3. 数据与资源合同

| 对象 | 切换/回退含义 |
| --- | --- |
| Mac 项目文件、容器 `/workspace` | 仍是同一项目目录；不会复制、删除或恢复历史版本 |
| 当前容器可写层 | 保留在原容器；不会复制到新容器 |
| 上一代容器 | 切换成功后停止并保留，以完整 ID 记录 |
| 新镜像内的软件 | 由用户提供的镜像决定；工具发现不等于版本或运行能力保证 |
| 项目配置 | 只变更合同明确允许的镜像字段，保留 name/platform 等其他声明 |
| 本机状态 | 切换当前容器身份，保存上一代快照与事务状态 |
| 构建镜像及共享缓存 | 不删除、不重打用户标签、不进行 prune |

**环境回退不会撤销新环境运行期间对项目文件的改动。** 预览、确认与成功输出均应简洁提醒。
容器外部依赖或数据库的变化不在回退承诺中。

### 3.1 单代回退与多次操作

- 回退目标为最近一次成功 switch 之前的项目环境，不支持任意历史选择。
- 成功 rollback 后消耗该回退记录；再次 rollback 返回“无可回退记录”，不在两代之间意外来回切换。
- 被 rollback 撤下的新容器停止并保留，标记为 retained，不自动删除。
- 新 switch 替换回退槽位时，更早的上一代同样转为 retained；预览必须列明此变化。
- retained 清单只是归属与资源账本，不承诺多代回退接口；文档提供核验完整 ID 后人工清理的方法。
- 旧环境和 retained 容器是有意保留资源，不可在验收中伪装成“零容器残留”。
- 验收检查“实际资源 = 当前代 + 上一代 + 明确保留集合”，额外出现的资源才是泄漏。

## 4. 命令与交互合同

以下均为未来拟议命令，尚未实现。

```bash
km env switch --image my-kali:v2 --dry-run
km env switch --image my-kali:v2
km env rollback --dry-run
km env rollback
km env recover --dry-run
km env recover
```

### 4.1 参数与确认

- `switch` 必须提供且只提供一个非空镜像引用；拒绝重复、冲突、未知参数。
- `rollback` 不接受用户任意指定容器 ID；只能使用项目自己的已验证上一代记录。
- `recover` 只接受当前项目未完成事务；不能自行选择其他事务目录或容器。
- 交互终端默认展示影响并要求明确确认；非交互调用须显式 `--yes`，否则在变更前返回用法错误。
- `--yes` 仅确认预览中的切换/停止行为，不绕过活跃会话、身份、平台或漂移检查。
- `--dry-run` 不询问确认、不写锁文件/状态/日志、不创建容器、不启动/停止容器，不拉取镜像。
- 预览结果不是执行授权令牌；真实执行必须重新读取并核验全部关键条件。
- 增加 `env` 管理命令后，重名工具仍可通过 `km run -- env ...` 调用。

### 4.2 预览至少包含

- 项目根与项目 ID；已固定的本地引擎身份。
- 当前容器完整 ID、状态、实际镜像 ID与平台。
- 目标镜像引用、解析后的内容 ID与实际平台；查询未成功的字段标 unknown。
- 哪个容器会停止、哪个会新建、哪个将进入回退槽位或 retained 清单。
- 项目文件不回滚、可写层不迁移的说明。
- 是否允许执行；不允许时列出明确原因与下一步操作。

### 4.3 返回值

| 情况 | 行为 | 退出码 |
| --- | --- | --- |
| 预检通过，或操作成功 | 输出明确结果和下一步 | 0 |
| 目标内容与当前一致且其他条件一致 | 明确 no-op；不创建新代、不改回退槽位 | 0 |
| 镜像缺失、平台冲突、身份冲突、会话活跃/未知 | 不开始变更，给出稳定错误分类 | 1 |
| 无上一代可回退 | 明确说明，不修改当前环境 | 1 |
| 存在未完成事务 | switch/rollback 阻断；指向 recover | 1 |
| 无未完成事务时 recover | 明确无需恢复 | 0 |
| 参数错误、非交互缺确认 | 用法错误，不进行变更 | 2 |
| 用户在变更前拒绝确认 | 明确未执行，退出值在合同冻结时固定 | 待冻结 |
| 取消、超时、恢复未完成 | 非成功，说明真实阶段与恢复入口 | 遵循既有错误模型并补合同 |

优先复用现有稳定 KM_* 分类；确需新增的事务错误标识要集中定义并加入 CLI 合同。

## 5. 切换前置门禁

真实执行取得项目变更锁后重新验证，不能只依赖锁外的预览。

1. 项目配置和本机状态可读取，且支持其 schema。
2. 当前 endpoint 为受支持本地引擎；本轮所有查询和变更固定到同一 endpoint。
3. 当前容器的完整 ID、名称、项目标签、挂载、镜像身份符合已有归属规则。
4. 目标镜像在本地存在；使用实际镜像元数据确认平台，不能仅根据标签或配置推断。
5. 目标平台与当前实际平台一致；旧配置中未声明平台不能被伪装为已声明。
6. 当前容器处于支持的 running/exited 状态；paused、restarting、dead 等独立处理，不自动 unpause。
7. 无活跃 km 会话，且会话查询可信；查询失败不等价于“无任务”。
8. 无其他切换/回退事务，上一代记录和 retained 清单可解析且归属一致。
9. 操作影响明确：停止旧容器会结束其中非 km 管理的进程，不能宣称能够完整识别任意后台工作负载。

锁必须覆盖执行、init、stop 与环境变更之间的互斥；状态查询继续只读。
恢复命令与 sessions/cancel 的交互需要单独测试，不能因新事务锁破坏原有显式取消能力。

## 6. 镜像引用与旧环境兼容

- 将用户目标引用解析为不可变内容 ID，候选容器按该内容 ID 创建，避免构建期间标签漂移。
- 配置仍保存用户选择的引用；状态保存实际内容 ID。提交前再次核验引用仍指向目标 ID。
- 如引用已漂移，拒绝提交，不重打标签、不静默跟随新内容。
- rollback 按记录的上一代容器 ID和镜像 ID验证，不能按当前标签重新创建“近似旧环境”。
- 上一代配置中的镜像引用若已漂移，第一版回退应在变更前明确拒绝，并提示恢复正确引用；
  不声称“任何条件下均可回退”，也不把本地 image ID 无说明地改写进共享配置。
- 容器被外部删除、镜像身份不符或挂载改变时，不凭名称接管替代资源。
- 旧项目首次使用新命令时才建立必要的新记录，不批量迁移所有项目。

## 7. 事务与中断恢复设计

### 7.1 持久化草案

建议使用项目本机状态目录 `.km/`，其内容继续不入版本控制：

```text
.km/
  state.json                 当前环境身份
  env/
    transaction.json         当前未完成事务及操作 ID
    previous.json            最近一次 switch 的上一代快照
    retained.json            有意保留但非当前/上一代的容器身份清单
```

实际文件布局可在设计评审时调整，但必须保持：

- schema 明确；未知版本拒绝写入，不尝试猜测修复。
- 事务记录包含操作类型、阶段、前后容器 ID、镜像 ID、配置/状态快照及哈希。
- 记录旧容器原先 running/exited 状态，便于失败恢复与 rollback 兑现状态。
- 临时文件写入、持久化及 rename 顺序明确；多文件写入不被称为天然原子事务。
- 使用唯一操作 ID及容器标签，使“Docker 已创建但客户端没拿到结果”的情况也可核验。
- 状态内容不保存凭据，不完整记录用户环境变量或任意项目文件。

### 7.2 旧二进制兼容是设计门槛

旧 km 不认识新事务文件，单独新增 journal 不足以阻止它在中间态运行。
实现前必须确定：事务相关 state schema 的兼容策略、旧二进制拒绝行为及最低支持版本。
建议扩展版本化本机状态，在进入首个容器变更前确保旧程序会明确拒绝新格式。
如果无法证明旧程序不会误用中间状态，不进入功能实现阶段。

### 7.3 建议状态转换

```text
PREPARED
  → CANDIDATE_CREATED
  → CANDIDATE_VERIFIED
  → OLD_STOPPED
  → COMMIT_INTENT
  → CURRENT_COMMITTED
  → FINALIZED
```

| 阶段 | 核心动作 | 失败/强杀后的要求 |
| --- | --- | --- |
| PREPARED | 在变更前持久化前态、计划和唯一操作 ID | 原环境未变，可确认后撤销事务 |
| CANDIDATE_CREATED | 以唯一代际名和本轮标签创建候选；不重用旧容器名称 | 即使未收到 ID，也能按精确操作标签发现并核验本轮候选 |
| CANDIDATE_VERIFIED | 验证身份、平台、必要运行依赖与有限基础探测 | 失败仅清理本轮候选；原环境可用 |
| OLD_STOPPED | 确认无活跃会话后停止旧容器，记录观察结果 | 未提交时按旧运行状态恢复；恢复失败保留事务和明确诊断 |
| COMMIT_INTENT | 持久化提交意图和前后快照 | 中途崩溃时普通变更命令阻断；recover 根据记录和实态决定收敛方向 |
| CURRENT_COMMITTED | 配置、当前 state 与上一代记录完成一致更新 | 不能仅因后续日志失败又悄悄退回；恢复应核实并完成收尾 |
| FINALIZED | 验证最终不变量，归档必要结果并清除未完成标记 | 返回成功；旧代保留状态与记录一致 |

设计评审必须冻结 COMMIT_INTENT 附近各个写入点的精确恢复规则，不允许实现时临时猜测。
不能仅根据日志阶段判断容器存不存在或运行与否，应与同一引擎的当前事实交叉核验。

### 7.4 候选验证限制

- 不挂载整个 HOME，不注入宿主 Docker socket，不自动加 privileged。
- 不执行项目自定义启动脚本，不扫描或修改项目文件。
- 必要挂载使用只读项目挂载；如何切换到正式可写挂载必须在合同阶段解决。
- 可采用单独的只读探测容器验证镜像，然后创建正式候选；两类资源都必须登记。
- 验证最终正式候选的配置、标签、挂载与镜像身份，不能只验证另一个探测容器。
- 不强制所有精选六项工具存在；至少验证 km 会话运行所需依赖，工具缺失另行展示。
- 流式展示构建以外的操作诊断；管理查询与候选探测各自有界，不沿用无限等待。

### 7.5 recover 行为

- `--dry-run` 只报告实际状态、计划恢复方向和风险，不修文件或容器。
- 正式 recover 要取得锁、校验归属和用户确认，且可重复调用。
- 提交点前优先恢复前态；提交点后优先完成新态，不任意切换方向。
- 无法确认资源身份时停止写操作，保留事务，不把错误当资源不存在。
- 对不明确的外部修改返回可操作诊断，不擅自覆盖配置。
- 无法自动恢复时也必须能输出完整容器 ID、原/目标关系与事务阶段，供人工核对。

## 8. 回退流程

1. 读取 previous 快照，验证记录完整且属于当前项目、同一引擎。
2. 核验当前环境与上一代容器都未被外部替换，平台一致，引用满足第 6 节要求。
3. 检查当前代无活跃任务、无未知会话状态；预览回退不会恢复项目文件。
4. 取得锁后重新验证，建立 rollback 类型的事务。
5. 确认上一代运行条件；保留其切换前的 running/exited 状态语义。
6. 停止当前代，提交上一代的配置和状态快照。
7. 当前代进入 retained 清单，消费 previous 回退槽位。
8. 验证状态、容器及资源账本一致后返回成功；所有失败沿用事务恢复规则。

## 9. 模块边界与改动范围

| 区域 | 预计职责 |
| --- | --- |
| CLI env 分派及帮助 | 参数、预览、确认、结果/错误渲染 |
| 项目状态/事务模块 | schema、快照、提交、恢复、上一代及 retained 记录 |
| runtime Docker 层 | 复用已有执行器；补最少必要的创建/检查操作，endpoint 全程固定 |
| session | 复用会话查询与状态判断，不重写进程清理内核 |
| status / doctor | 展示当前代和未完成事务，避免中间态被报为正常 |
| 测试 | fake 故障注入、真实 Docker、安装包验收 |

不要把所有事务操作塞进一个超长 CLI 函数；也不要抽象成通用工作流引擎。
先绘制现有读写调用关系，再选择最小结构调整。

## 10. 分阶段实施任务

### P0：重新确认基线与冻结设计

- 开发启动时核对实际分支、HEAD、工作区与上一轮交付状态，不假设 master 已包含所有功能。
- 当前已存在的未跟踪文档/备份原样保留，不混入提交、不清理。
- 经后续执行授权后，基于包含 tool-discovery 的正确提交创建建议分支。
- 冻结命令合同、旧二进制策略、提交点、恢复状态表、回退记录轮换规则。
- 明确正式候选与只读探测容器的区别；列出不变量。

完成门槛：设计不存在“尚未决定如何恢复”的写入步骤。

### P1：预览与前置门禁

- 先覆盖身份冲突、镜像缺失、平台不同、活跃会话、未知状态等负向测试。
- 实现只读预览；复用身份校验和会话逻辑，不产生变更资源。
- 验证人类输出能准确说明保留内容与数据回退边界。

完成门槛：所有拒绝场景证明没有发生容器或文件变更。

### P2：事务存储与恢复内核

- 实现版本化记录、前后快照、幂等恢复与互斥。
- 在每个持久化步骤与 Docker 操作边界注入失败。
- 测试“操作成功但响应丢失”，避免重复创建或遗漏清理。

完成门槛：fake 测试覆盖每个阶段的前态恢复/后态收尾，旧客户端误用问题已验证。

### P3：真实 switch

- 实现候选验证、旧环境停止、提交、上一代保留与最终核验。
- 相同目标内容走 no-op，不耗费回退槽位。
- 目标标签在过程中改变时拒绝不一致提交。

完成门槛：真实切换成功且失败不丢原环境；原有命令读到一致状态。

### P4：rollback 与重复操作

- 实现单代回退、回退槽位消费、retained 记录。
- 覆盖 switch→switch→rollback、switch→rollback→rollback 等明确语义。
- 验证文件修改仍然保留，避免用户误以为环境回退等于数据回退。

完成门槛：无意外双向切换，无按名称误操作，无账本外遗留资源。

### P5：回归、独立审查与交付

- 审查事务顺序、真实检查覆盖范围、资源归属和兼容性。
- 执行单测、race、vet、build、真实集成及安装版验收。
- 更新用户指南、CLI 合同、架构/ADR、CHANGELOG 与验证记录。

## 11. 测试矩阵

| 类别 | 场景 | 必须证明 |
| --- | --- | --- |
| 正常切换 | 镜像 A→B，工具内容不同 | 新命令实际在 B 执行，旧 A 停止并有记录 |
| 回退 | B→A | 容器/镜像身份恢复，B 保留且退出当前代 |
| 文件边界 | B 修改共享文件后回退 | 文件修改仍在；说明与行为一致 |
| 可写层边界 | A 内有非共享文件 | 文件仍在 A；B 不凭空继承 |
| no-op | 相同镜像内容，含不同标签指向同 ID | 无新增代际，无停止旧容器，无消费回退槽位 |
| 本地镜像缺失 | 提供不存在的 ref | 非零，不拉取、不创建 |
| 平台 | 配置缺失/显式声明/实际不同 | 基于实际平台判断，不伪造兼容 |
| 会话 | 活跃、STALE、未知、脚本缺失且登记状态不明 | 活跃/未知不切换；缺脚本不直接证明无任务 |
| 容器状态 | running/exited/paused/restarting/dead | 分别按合同处理，不统称已停止 |
| 归属 | 名称重用、ID不符、标签/挂载变化 | 拒绝并且不操作其他资源 |
| endpoint | 远程、漂移、执行中默认 context 改变 | 拒绝或保持原固定 endpoint |
| 镜像漂移 | 检查后标签改指向 | 不创建/提交非目标镜像；回退引用漂移亦明确处理 |
| 并发 | run/init/stop/switch 同时进入 | 互斥不变量成立，查询及合法取消路径不失效 |
| 外部编辑 | 事务中修改 .km.json | 不覆盖外部修改，提供冲突诊断 |
| I/O 故障 | 快照/状态写入失败、磁盘满、rename 失败 | 恢复方向清晰，旧配置/记录不丢失 |
| 引擎故障 | stop/create 成功但响应丢失、Docker 短暂断开 | 按实际资源核对，避免误报不存在 |
| 强杀 | 在每个阶段边界终止宿主进程 | 重新启动后能识别事务并显式恢复 |
| 二次恢复 | recover 重复调用 | 幂等、不额外创建容器或改变成功状态 |
| 回退目标丢失 | 上一代被外部删除 | 非零，当前环境不被停止/替换 |
| 多项目 | A 切换期间 B 执行/查询 | B 不受影响，ID与资源不串用 |
| 数据结构 | 缺字段、未知 schema、部分文件损坏 | 拒绝写操作，原始证据保留 |
| 旧二进制 | 读取新事务/新状态 | 明确拒绝，不误用中间态 |
| 安装包 | 从 dist 安装后完整操作 | 不依赖开发 bin/km、源码路径或开发环境状态 |

至少两个真实测试镜像，内容区别通过确定性文件/命令证明，不依赖外网包仓库是否恰好可用。
ARM/AMD 测试期望按实际测试平台构造，避免再次硬编码冲突平台。

## 12. 验证命令清单（未来执行，本轮未运行）

```bash
make fmt-check
go vet ./...
go vet -tags=integration ./...
go test -count=1 ./...
go test -race -count=1 ./...
go build ./...
go test -tags=integration -count=1 -timeout 15m -v ./tests/integration/
```

新增测试命名建议 `TestEnvSwitch*`、`TestEnvRollback*`、`TestEnvRecover*`。
逐步确定有界超时；不以无限重试掩盖竞态，调大超时必须有测量依据。
所有真实测试仅操作本轮创建并核验的临时项目与资源；Docker 不可用时记录未验证。

## 14. 最终完成门槛

- [ ] 预览无变更，输出与实际执行影响一致。
- [ ] 用户显式确认后可可靠切换本地同平台镜像。
- [ ] 活跃/未知会话、身份冲突和不支持的容器状态不被绕过。
- [ ] 镜像内容身份固定；标签漂移不会静默改变目标。
- [ ] 单代回退兑现配置、容器及原运行状态，且不会回滚共享文件。
- [ ] 每个事务阶段的失败、强杀和重试有当前代码对应的证据。
- [ ] 新旧状态 schema 的兼容策略经过实测。
- [ ] 当前/上一代/retained/临时候选资源账本与实际资源一致。
- [ ] 原有 run/shell/status/doctor/sessions/cancel/tools 回归通过。
- [ ] 安装版验收通过，文档说明完整，未验证条件明确。

任何一项缺少证据，都应标为未完成；不以“总体 PASS”覆盖具体遗漏。
