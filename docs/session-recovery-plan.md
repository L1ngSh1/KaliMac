# KaliMac 下一阶段计划：会话查看与显式恢复

> 状态：执行中（本文件为冻结的计划与行为合同基线；执行进度见
> `docs/session-recovery-progress.md`）

## 一、阶段目标

让用户在异常退出后，通过 KaliMac 自身完成：

```text
发现阻断 → 查看会话 → 明确选择取消 → 确认取消结果 → 恢复执行
```

计划新增：

- `km sessions`：查看当前项目的会话。
- `km cancel <id>`：显式取消当前项目的指定会话。

**核心原则：降低恢复操作成本，不改变"可能仍在运行的任务必须被保护"的语义。**

## 二、范围与非目标

### 本轮范围

1. 核对当前提交与 CI 基线。
2. 审查会话查询、取消和并发控制链路。
3. 制定两个命令的行为合同。
4. 实现命令及必要的局部整理。
5. 修复 cancel 过程中偶发的 `/proc/.../stat` 诊断噪音（试用记录 F2）。
6. 补齐回归、真实验收、文档和证据。

### 本轮不做

- 自动取消、批量取消、跨项目取消。
- 全仓库冗余清理或架构重构。
- 新增工具集合、运行时后端或插件系统。
- 热调用性能优化。
- 自动提交、推送、打标签或发布。

## 三、实施阶段

### S0：确认基线

核对工作区、提交范围及远端 CI 实际结果；区分本地通过、远端通过和未验证项目；
特别核对 `install.sh` 的行为变更（KM_BIN 来源覆盖，已在 prerelease 阶段二完成真实验收，
不是纯文档变更）；记录当前版本、提交、平台、镜像内容身份和测试结果。
amd64 未实测的事实继续保留。

### S1：会话链路专项质量审查

审查范围：`internal/cli`（执行、诊断与恢复提示）、`internal/session`（登记、查询、
取消与清理）、`internal/runtime`（endpoint、容器身份、命令执行）及对应测试。

重点问题：查询与归属校验是否重复或存在差异；查询失败是否被误判为无会话；取消和
自然退出并发时是否正确；活跃任务持有的项目锁是否会阻止恢复命令；SID、PID 与进程
退出竞争是否影响清理；F2 噪音是否仅为正常竞争还是隐藏实际错误。

完成标准：每项问题具有代码位置、触发条件、影响和验证方式；仅实施与本轮目标相关、
有证据支撑的整理；不通过吞掉 stderr 或放宽断言掩盖问题。

### S2：冻结交互与行为合同

#### `km sessions`

| 场景 | 行为 |
|---|---|
| 当前项目没有会话 | 明确显示无会话，退出 0 |
| 存在会话 | 显示完整可复制 ID、状态及可靠取得的辅助信息 |
| 会话状态不确定 | 显示未知，不解释为已结束 |
| 查询失败或引擎不可达 | 输出稳定错误标识，非零退出 |
| 项目或容器归属不匹配 | 拒绝查询目标容器内的会话 |

要求：只读，不启动已停止容器、不安装脚本、不清除登记；不伪造缺失的开始时间、命令
或进程信息；脚本缺失、容器停止的表现单独定义。

#### `km cancel <id>`

| 场景 | 行为 |
|---|---|
| 当前项目的活跃会话 | 取消指定会话，并核验终态 |
| 已登记但已结束的会话 | 幂等处理，明确说明 |
| 完全未知的 ID | 明确报错，不宣称取消成功 |
| 非当前项目的会话 | 拒绝，不操作其他项目 |
| 取消超时、失败或终态未知 | 非零退出，保留诊断信息 |
| 参数缺失或格式错误 | 用法错误，不发起取消 |

要求：完整 ID 精确匹配，不支持模糊前缀；显式指定 ID 即为取消意图，不默认自动取消；
不停止整个容器，不影响其他项目；"成功"对应约定清理范围内的任务结束与登记收尾，
而非仅发出信号；既有主动脱离会话进程的行为边界继续明确保留。

合同冻结前必须解决：①查询、取消与执行锁如何协作；②如何避免检查完成后状态变化
造成错误操作；③"未知 ID"与"已完成会话"的证据如何区分；④超时、退出码、稳定错误
标识如何沿用现有约定。

#### 审查收口补充（2026-09-17）

- **信息状态 vs 未知 ID**：容器未运行、脚本未安装属于「查询不可执行的信息状态」，
  sessions 与 cancel 均说明原因并**退出 0**（cancel 无可作用对象，不报
  KM_SESSION_UNKNOWN）；「列表中不存在该 ID」只在**查询成功**时判定，报
  `KM_SESSION_UNKNOWN` 退出 1。实现与测试已同步（TestCancelInfoStatesExitZero）。
- **外部取消的退出码**：被 `km cancel` 取消的运行中任务，其客户端退出码为工具真实
  状态（TERM=143 原样透传）；Ctrl-C 的 130 语义不变。
- **F2 证据的三层职责**（审查定稿）：①**源代码守卫**：检查预期的重定向顺序，防止
  旧写法重新引入；验证代码形态，不单独证明运行行为。另有重定向机制行为测试（相同
  shell、输入重定向指向确定不存在的文件）：旧顺序 stderr 出现 "cannot open"、新顺序
  为空——稳定验证重定向机制本身。②**容器内对照实验**：进程翻涌下旧写法 220 条诊断、
  新写法 0 条；支持修复有效，但并发负载存在随机性，不作为每次必现的保证。③**端到端
  回归**：10 次真实活跃会话取消完成且未观察到该噪音；旧写法在另一轮 10 次取消中同样
  未复现，故该测试用于检查真实取消链路，不作为稳定区分新旧实现的依据。三者职责分开。

### S1 审查结论（2026-09-16，代码位置与验证方式）

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| 归属校验重复/差异 | run 门禁（`internal/cli/run.go` verifyStackForMutation → `init.go` verifyContainerIdentity）与 doctor 报告（`doctor.go` 对称规范化）定位不同：门禁 vs 展示。恢复命令采用门禁的容器归属部分，**不含镜像内容检查**——镜像漂移不应阻止只读查询与定向清理（KM_IMAGE_DRIFT 仍阻断 run/init，报告渠道不变） | run.go:48-90, init.go:33, doctor.go |
| 查询失败误判 | verifyNoActiveSession 三态严格（err/exit≠0/解析失败 → KM_SESSION_UNKNOWN 阻断，不当作无会话）；doctor 会话检查 M2 后已分类计数。新命令沿用同一严格语义 | sessionctl.go:33-56 |
| 取消与自然退出并发 | km-ctl 协议幂等覆盖：目录消失=3、exit 文件存在=0、排空后 0、未确认=4；Manager 已透传 3/4 | scripts.go kmCtlSh, prod.go Cancel |
| 锁协作 | run/shell/init 持项目执行锁；**sessions/cancel 不取锁**——前者只读，后者是定向控制操作，必须恰在锁持有人卡死/死亡时可用；并发安全由容器侧协议幂等兜底 | run.go:114-121, 约定 |
| SID/PID 退出竞争 | km-run 排空设计（R1）+ alive 排除僵尸 + sweep 组空清扫；TPID 秒级复用窗口与会话目录短命，风险可接受（记录在案） | scripts.go kmRunSh |

### S2 合同冻结结论

- **锁**：sessions/cancel 不获取项目执行锁（S1-4）。
- **TOCTOU**：先 Sessions 列表确认归属与存在 → 完整 ID 精确匹配 → Cancel → 按协议码
  解释；列表与 cancel 之间的状态变化由 0/3 幂等兜底，不会误伤其他会话。
- **未知 vs 已完成**：列表中不存在该 ID → `KM_SESSION_UNKNOWN` 退出 1（不宣称成功）；
  列表中存在而 cancel 返回 3，或该 ID 列表时已 STALE → 幂等成功且消息明确区分。
- **退出码沿用**：0 成功（含幂等，消息区分）；1 环境/状态失败（KM_* 标识 + 保留诊断）；
  2 用法错误（KM_USAGE）。会话 ID 格式 `^s[0-9a-f]{16}$`（NewSessionID），非法即用法错误。
- **容器停止**：两命令均不启动容器；明确定义输出（sessions：说明登记将随下次执行清扫；
  cancel：说明无需取消）退出 0。
- **km-ctl 缺失（exit 127）**：说明「脚本未安装（init 后首次 run/shell 时安装）」退出 0
  （无会话可恢复；与 doctor M2 分类一致）。
- **输出**：sessions 有会话时 stdout 为 `ACTIVE <id>` / `STALE <id>` 行（完整 ID 可复制），
  辅助提示走 stderr；空时 stdout 明示「当前项目无会话」。

### S3：小步实现

拆分：①补充失败场景测试，定位 F2；②整理必要的共享查询逻辑，保持现有行为；
③实现 `km sessions`；④实现 `km cancel <id>` 及并发控制；⑤将现有阻断提示更新为

校验；取消入口不因执行锁而失效，也不通过取消全部锁保护解决问题。

### S4：验证与真实验收

必测：参数与输出（缺参/非法 ID/未知 ID/完整 ID 可复制）、查询（无会话/活跃/过期/
未知/脚本缺失/容器停止）、取消（正常/重复/自然退出竞争/超时与失败）、隔离（跨项目
ID、A 忙碌时 B/C 不受影响）、清理（后台管道/停止态/忽略 TERM）、故障（Docker 不可达/
容器消失/状态读取失败）、回归（原有 run/shell、退出码、终端恢复、文件共享）。

关键端到端：长任务 → 强杀宿主 km → 新执行被阻断 → `km sessions` 找到会话 →
`km cancel <id>` → 核验清理 → 再次执行成功（连续三轮）。

完成标准：单测、race、vet、build 通过；真实集成无意外跳过；本轮资源零残留、无跨
项目影响；F2 有针对性证据证明已修复；其他真实错误仍然可见。
